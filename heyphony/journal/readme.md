# journal

*the dated record, so the reasoning survives the code*

the readme explains what this is. this folder records how it got that way, one entry per working session, in the order things were decided rather than the order they turned out to matter. it is append-only: an entry that turned out to be wrong gets a correction in a later entry, not a quiet edit, because the value of a journal is that it is what somebody actually thought at the time.

alongside the entries there are two explainer pages: [softphones, from zero](softphones.md), which walks the mechanism without assuming prior knowledge, and [what a softphone was for](pbx-vs-softphone.md), which compares the job it was built for with the job it was bent into. neither is an entry, because neither happened on a particular day.

each entry has four parts: what was decided, what was built, what was refused, and what is still unproven. the fourth part is the one that keeps the lane honest, because "built" and "works" are different words and the gap between them is where most agent tooling quietly lies.

- [what a softphone was for](pbx-vs-softphone.md): the same object beside a pbx and beside an agent, in one table
